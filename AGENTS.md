# eton Development Rules

**Rule one: no comments in code. Never write `//` or `/* */` comments — not in new code, not in modified code, no exceptions.**

- Express intent through naming, structure, and commit messages. Background information that must be preserved (version differences, hard-won findings, non-obvious constraints) belongs in this file, never in code.
- Scope: all first-party source files in the repository (`src/` .c/.cpp/.h/.rc plus root-level tool sources). `deps/` contains third-party prebuilt libraries — never modify it.

## Known Findings (from past debugging — do not regress)

- Scintilla's DirectWrite backend selects CJK fallback fonts using the en-us locale by default, so Han characters fall back to a Japanese font with wrong glyph shapes (e.g. an isolated dot inside "类"; Scintilla bug #2027). `DwFontLocale()` in `editor.c` follows the system locale and falls back to zh-CN for non-CJK locales — do not remove.
- The Markdown preview (`dwtext.cpp`) maps CJK Han fallback to SimHei: Microsoft YaHei's "类" glyph has a vertical-stroke tip that protrudes outside the character box and reads as an extra dot; SimHei keeps every stroke inside the box.
- The preview's typography is monospace by design: `FontsEnsure` in `mdview.c` uses Consolas for body/bold/emph/headings (GDI + Dwt tables, 12 face strings) so the rendered view matches the editor/block-edit overlay; only math stays Cambria Math. Do not switch the body back to a proportional face without revisiting the block-edit font question.
- Bundled Lexilla markdown lexer style numbers: 2/3 strong, 4/5 emphasis, 6..11 are H1..H6, 12 pre-char marker, 13/14 list marker, 15 blockquote, 18 link, 19..21 inline code.
- The Mermaid native renderer (`mermaid.c`) has two flow layouts: flat (`FlowLayout`) and compound (`FlowLayoutCompound`, flowchart with subgraphs). `FlowDraw` routes a TB edge as horizontal only when `b->layer == a->layer && b->rank == a->rank` — the flat path must keep `layer = rank` on every node or same-rank edges across clusters misroute.
- merprobe PNG mode draws at `UI_Scale(60)` from the left; its zoom argument is percent ×100 (pass `100` for 100%, `1` also normalizes to 100).
- Scintilla uses ONE document-wide line height: `ViewStyle::FindMaxAscentDescent` takes the max ascent/descent over ALL defined styles (realized fonts, used or not), so any style sized above STYLE_DEFAULT (markdown H1..H6 get `g_fontSize + (11 - s)` in `ApplyLexer`, max +5) inflates every line of that document. Non-markdown docs therefore get the base spacing only (`ApplyLineSpacing`: extra = fontPx/13 per side ≈ 1.16× em, matching Windows Notepad's Consolas line pitch = winAscent+winDescent ≈ 1.159× em), while markdown docs run ~1.6× em because of the heading styles — this asymmetry is intentional (md keeps the looser pitch, txt matches Notepad); per-line line heights are impossible in Scintilla.
- The bundled md4c (deps/md4c, 0.6-era tree) callbacks carry NO source offsets, and `MdBlock`/`MdRun`/`MdItem` carry no source positions either. The only source mapping for "double-click a block to edit" in the preview is `MdEditScanBlocks` in `mdedit.c`: a line-classifying scanner that mirrors md4c top-level block splits (ATX headings / HRs / fenced code are their own blocks; `---`/`===` after paragraph text merge as setext; quote and list runs absorb lazy continuations; a blank line inside a list run is bridged when the next non-blank line is a same-type marker or indented ≥2). Two guards keep it safe and must not be removed: (1) block editing is enabled only when the scanner's block count equals `V.root->nChildren` (exotic structures — footnote definitions, tables glued to a paragraph — silently disable the feature), and (2) `MdEdit_Commit` re-verifies the editor's `[start,end)` bytes against the snapshot taken when the overlay opened — on mismatch the commit is dropped. `MdItem.blk` is stamped from `V.layIdx` in `ItemPush` and is the render→block link.
- The top chrome merges the TITLE BAR into the tab row, Win11-Notepad style: `WM_NCCALCSIZE` in main.c reclaims the caption band (`rgrc[0].top = rgrc[2].top + frameY`), the tab bar (row 1) is the caption — its empty areas drag the window (`SC_MOVE|0x2` from tabbar.c) and double-click maximizes; the top-right `CaptionButtonsWidth()` (3×46@96, drawn by `CapPaint` in main.c WM_PAINT, hover via main's WM_MOUSEMOVE) hosts min/max/close. Row 2 is the command bar (toolbar.c, `CMDSTRIP_HEIGHT_96`): it STARTS with seven TEXT menu buttons (kBtns icon -3, cmd = group index into g_hMenuRoot; click → `WM_APP_STRIP_GROUP` → TrackPopupMenu of that submenu), then a separator, then the regular icon buttons (`TbRects` takes hwnd because text-button widths are measured and cached per fontGen/dpi in `MenuTxtWidths`). Row 1's left zone (`MENU_W_96`) shows the APP ICON (click → `WM_APP_STRIP_MENU` → root popup), right zone (`NEW_W_96`) is `+` new tab; close `x` only on active/hovered tabs. There is NO native menu bar or caption: `I18n_BuildMainMenu` returns a root POPUP kept in main.c `g_hMenuRoot` (rebuilt by `RebuildMainMenu`), shown via TrackPopupMenu from the ≡ zone; menu state refresh rides `WM_INITMENUPOPUP` → `UpdateMenuChecks` which walks ALL submenus of the root. `DarkMenuEdge` is gone; Alt/F10 menu mnemonics do not exist. Do not re-add SetMenu.
- Typora-style block editing (mdedit.c): opt-in via View menu `IDM_VIEW_MDLIVE` (global `g_mdLiveEdit`, default FALSE, persisted as `mdliveedit` in session.ini); with it off the full-window preview is a pure viewer. Entry is single-click (no-drag, non-link) in full-window preview via mdview.c `ClickToEdit`; `MdView_SoftRefresh` must keep its `LayoutEnsure(scrollY + clientH + margin)` after restoring the scroll — `LoadContentEx` resets `V.scrollY` to 0 and only lays out the top 2 screens, so without the extension `MdView_BlockRect` fails for blocks deeper in the document and CommitQuiet silently CLOSES the overlay (the "preview flashes and edit mode disappears while typing" bug); ↑/↓ at a block's first/last line chain to the neighbor via commit → `MdView_SoftRefresh` → `MdEdit_OpenAt`; Enter at the end spawns a new block (`MdEdit_BeginNewRange`), Backspace at position 0 merges into the previous block by deleting the blank separator (or the previous block's trailing newline when blocks are adjacent); typing arms main-window timer 4 (300ms) whose `MdEdit_Tick` → `CommitQuiet` applies via target-replace, refreshes, re-aligns E.start/E.blk from a fresh scan and repositions the overlay without touching focus. Overlay SCN_ notifications are routed in main.c `WM_NOTIFY` via `MdEdit_OnNotify` BEFORE `Editor_OnNotify` (which ignores them: overlay is not in g_docs). Guard failure surfaces as `STR_MD_NOBLOCK` on status-bar part 0 (transient; `Editor_UpdateStatus` reclaims it).

## Build and Verification

- Build: run `build.bat auto` from the repository root; success prints `BUILD_OK`. The output is `eton.exe` in the root (Scintilla/Lexilla statically linked).
- Current dependency: Scintilla 5.6.9 (2026-11-02), compiled from source into `deps/scintilla/libscintilla.lib`; the link line needs `d2d1.lib dwrite.lib`. Lexilla 5.5.5 (2026-10-31). Markdown lexer styles 0-21 are unchanged from 5.4.9; 5.5.x adds SCE_MARKDOWN_FRONT_MARK/FRONT/FRONT_KEY (22/23/24) for front matter.
- Rebuilding the dep libs: put `scintilla/` and `lexilla/` source trees under one root, then run `deps\make-deps.cmd <src-root> <out-dir>` inside an MSVC x64 environment; copy the two `.lib` files plus changed headers from `scintilla/include` and `lexilla/include` into `deps/`.
- For UI verification, use PowerShell screenshots (CopyFromScreen / PrintWindow) with pixel analysis; no extra dependencies.
